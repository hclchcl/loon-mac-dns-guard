# 合并说明，不是完整配置。请先备份，切勿整段替换现有文件。

# 1. 在现有 [General] 下合并，同名键只保留一行：
[General]
hijack-dns = *:53

# 2. Loon → 配置 → DNS 服务器：
# 查询回落 = 关闭
# DoH 流量模式 = Rule
# 包含系统 DNS 地址：可关闭则关闭；若不能关闭，保留并检查实际查询记录。
# 插件的 PROXY = 已有的可用境外代理策略，不能选择 DIRECT 或直连回退组。

# 3. 检查所有全局 DNS 来源。
# doh-server/dns-server 是追加项，插件不能清除主配置/其他插件中的服务器。
# 从主配置和其他插件移除不需要的全局 DoH/DoQ/DoH3；不要把阿里与
# Cloudflare 放在同一个全局并发列表，否则不能保证国内/国外解析分流。
# 检查已有 [Host]、SSID DNS 与订阅的 [Host]/[DNS]，不能只看插件内容。

# 4. 服务器地址使用域名的节点：
# 对每个现有节点或 [Remote Proxy] 订阅行追加/修改这一参数：
# server-dns="https://223.5.5.5/dns-query,https://223.6.6.6/dns-query"
# 保留原订阅地址、鉴权及其他参数；不要把实际订阅内容提交到公开仓库。
# 使用 IP 端点和正常 TLS 证书校验，不需要先解析 DNS 服务器的域名。
# 这是建立代理前的直连加密引导解析，解析器能看到节点服务器域名。
# 如果对应节点域名已匹配 [Host] 中的指定 DNS/映射，Host 的优先级更高，
# 应先核对并修正这个具体条目；不能假定添加 server-dns 就一定生效。
# 不支持 server-dns 的旧版请升级或为具体节点域名建立加密 DNS Host 映射。
# 不要对所有域名设置 server:system，也不要额外开启普通 DNS 回落。

# 5. 使用 TUN 接管，核对系统 DNS 的 IPv4/IPv6 地址是否确实进入 Loon。
# 已被 bypass-tun、进程绕过或其他 VPN 接走的流量不受插件端口规则保护。
# 不盲目移除整个局域网绕过列表，以免损坏内网业务。
# 如需将某个实际系统 DNS 的 IPv4 地址单独纳入 TUN，Build 1007+ 支持
# include-tun 的 /32 路由；应按当前地址精确配置并检查与绕过路由的优先级。
# include-tun 不支持 IPv6，IPv6 DNS 的接管需单独检查。

# 6. 重连后看 DNS 与请求记录；本地规则优先于插件规则。
# UDP DNS 应被接管或拒绝；拒绝不等于透明代答成功。
