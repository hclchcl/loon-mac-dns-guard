# 制作检查记录与待测范围

日期：2026-10-28（Asia/Shanghai）；实机测试补充于 2026-11-04

## 2026-11-04 实机测试（国内分流版 v1.2.0）

环境：Loon for Mac 0.5.0 (1011)，TUN 模式，`ip-mode = v4-only`，查询回落关闭，DoH 流量模式 Rule，“包含系统 DNS 地址”开启，主配置另有 `dns-server = system`。4 个订阅均设置 `server-dns` 为两个阿里 IP 端点。全程未断开 Loon；只在插件详情里切换 PROXY 绑定，并新增一个 url-test 策略组。

数据来自 Loon Dashboard 的 DNS 记录，以及从本机经 Loon 发出的 DoH 请求（同一 HTTP/2 连接内连续 14 次查询的中位数，每个地区测 3 轮）。

| PROXY 绑定 | 经 PROXY 的 Cloudflare 查询 | 新建连接首个查询 |
| --- | --- | --- |
| 美国手动策略（家宽节点） | 161–205 ms | 404–423 ms |
| 新加坡手动策略 | 154–200 ms | 737–931 ms |
| 日本手动策略 | 87–102 ms | 669–950 ms |
| 香港手动策略 | 41–43 ms | 220–344 ms |
| `DNS 出口`（香港节点 url-test，33 个节点） | 42–46 ms | 218–321 ms |
| 对照：阿里 `223.6.6.6` 直连 | 11 ms | 88–96 ms |

- Dashboard 中，绑定美国时经 Cloudflare 的实际解析多为 370–980 ms，个别 1.8–2.1 s；切换到香港后，逐个打开 10 个未缓存的境外站点，解析耗时为 50–545 ms，中位数约 230 ms，另有一次 3.24 s 的离群值。20 个站点同时打开时为 600–850 ms。改为绑定香港节点的 url-test 组 `DNS 出口` 后，再逐个打开 9 个新站点，6 个为 43–88 ms，其余为 200 ms、573 ms、1.19 s，中位数约 88 ms。新建组与切换绑定都没有断开 Loon。
- 662 条 DNS 记录只涉及 4 个服务器：`223.6.6.6`、`223.5.5.5`、`1.1.1.1`、`1.0.0.1`。尽管开启了“包含系统 DNS 地址”且主配置含 `dns-server = system`，路由器 DNS 没有出现。
- Host 映射的匹配开销：先直接查询阿里使其缓存，再经 Loon 打开 12 个清单内站点，Loon 记录的解析为 12–53 ms，中位数约 30 ms；同一时段直接查询阿里（复用连接）为 10–26 ms。差距在网络波动范围内，12,595 条映射不是瓶颈。
- 抽查 40 个常用国内站点，38 个已被国内清单覆盖，未覆盖的是 `www.v2ex.com`、`www.cnbeta.com.tw`。多级子域名（如 `connectivitycheck.platform.hicloud.com`）由 `*.hicloud.com` 正确匹配到阿里 DoH，耗时 336 ms。
- Loon 自身的联网检测请求同一主机时，不经 Host 映射而走 Cloudflare，耗时 0.6–2.1 s，返回的是境外地址。
- 节点域名经 `server-dns` 解析，多为 10–120 ms，偶尔约 300 ms，没有失败记录。同一节点域名在 TTL 仍为 599–600 s 时被连续重复解析，说明节点解析结果没有在连接之间复用。
- DNSPod `1.12.12.12` 与 `120.53.53.53` 的 IP 写法 DoH 在本网络中约 1.3–1.4 s，不适合作为附加的节点引导端点。

结论：对网页打开速度影响最大的是 PROXY 绑定在哪个地区，插件规则本身不是瓶颈；国内清单覆盖充分。以上为单一网络、单一时段的测量。

### 2026-11-06 补充：两天真实流量与 Host 多服务器写法

- 两天内 Loon 记录的 3,653 个已访问域名中，1,123 个由国内清单匹配。其余 2,530 个经 PROXY 查询 Cloudflare 后，只有 40 个（28 个注册域名）解析到 GeoIP CN 地址，清单对实际国内流量的覆盖率约 97%。这 40 个在上游 v2fly 最新数据中均未作为国内域名收录，因此不加入公共清单。
- 日常解析耗时：经 Cloudflare 的网页域名中位数 73 ms、p90 386 ms；经阿里的中位数 17 ms、p90 117 ms。
- 为一个不在清单内的国内站点添加主配置 Host `<域名> = server:https://223.6.6.6/dns-query,https://223.5.5.5/dns-query` 后，Loon 界面接受并写入配置，但该域名没有任何解析记录：第一次请求被兜底规则送往代理，耗时 4.2 s，第二次超时。对照的另一个同类站点没有映射，经 Cloudflare 解析到国内地址后正常直连。删除这条映射后，原站点恢复正常。单条 Host 映射不能写多个服务器，国内端点的单点问题无法在插件内解决。
- 订阅缺少 `server-dns` 时，节点域名走全局 DNS，即经 PROXY 访问 Cloudflare，中位数 66 ms，最慢 2.17 s，并与 PROXY 绑定的节点组形成循环依赖。补上 `server-dns` 后，修改后的 54 次节点域名解析全部走阿里，平均 67–73 ms。

## v1.1.0 国内分流版的对照测量

日期：2026-10-28，作者本机所在网络（Loon for Mac 0.5.0 运行中）。

- 国内分流版现含 13 条规则、325 条 Host 映射，其中 313 条为国内解析匹配项；`docs/domestic-domains.txt` 与之逐条一致。
- 新增 41 个注册域名来自 50 个常用站点（其中 42 个原先不在清单内）的对照：Cloudflare DoH 经代理查询，阿里 DoH 从物理网卡直连查询，两边返回的前两个地址各做一次 TCP + TLS 握手计时。结果汇总见 [CDN 优化说明](cdn-optimization.md)。
- 同一网络中，阿里与 DNSPod 的域名 SNI 写法 DoH 握手超时，IP 写法正常；插件端点均为 IP 写法。
- 对 28 个已在清单内的国内 CDN 主机做了三轮阿里 DoH 解析与连通测试：两个阿里端点分别为 80/83、81/84 次返回可连地址，失败只出现在 `s1.hdslb.com` 的单一故障节点。

以上为单一网络的测量，不代表其他网络或时段；没有据此验证 DNS 出口或泄漏检测结果。
